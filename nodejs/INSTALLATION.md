# How the Node.js package builds

`npm install librats` compiles everything on the user's machine; there are no
prebuilt binaries. Three package scripts run in order.

1. **preinstall** — `scripts/build-librats.js` configures and builds the librats
   C++ library as a static archive in `build-native/`, with CMake.
   - Sources: inside a librats repository checkout it builds the repository's
     own `src/` (two levels up); in an installed package it builds the snapshot
     in `native-src/`, which `npm run prepare` copied there before publishing.
   - Windows: finds Visual Studio 2017–2022 or its Build Tools with `vswhere`
     (MSVC is required, since node-gyp links the addon with it) and builds
     Debug and Release into `build-native/lib/{Debug,Release}/rats.lib`.
   - Linux and macOS: Unix Makefiles, `-j4`, into `build-native/lib/librats.a`.
   - Archives from an earlier run are deleted first, so a failed build cannot
     pass for a successful one.
2. **install** — `node-gyp rebuild` compiles `src/librats_node.cpp` (an N-API
   addon over the C API in `src/librats/bindings/rats.h`) and links it against
   that archive, producing `build/Release/librats.node`.
3. **postinstall** — `scripts/postinstall.js` checks that the addon exists and
   prints a short usage hint.

`npm run verify` (`scripts/verify-installation.js`) loads the addon and starts
and stops a node.

## Requirements

- Node.js 20 or newer
- CMake 3.14 or newer
- A C++17 compiler: Visual Studio (Build Tools) 2017+ on Windows,
  `build-essential` on Linux, Xcode Command Line Tools on macOS

## Package layout

```
nodejs/
├── package.json        install scripts; "files" lists what is published
├── binding.gyp         node-gyp build of the addon
├── lib/index.js        JS wrapper that loads the addon
├── lib/index.d.ts      TypeScript definitions (the API reference)
├── src/librats_node.cpp
├── scripts/            build-librats, postinstall, prepare-package, verify-installation
├── examples/
├── test/test.js
├── native-src/         generated by `npm run prepare`: CMakeLists.txt, src/, cmake/, 3rdparty/
├── build-native/       generated: the CMake build of librats
└── build/              generated: the node-gyp build of the addon
```

## Working on the binding

From a repository checkout:

```bash
cd nodejs
npm install          # builds librats from ../src, then the addon
npm test
```

After changing librats sources, rerun `node scripts/build-librats.js` and then
`npx node-gyp rebuild`. After changing only `src/librats_node.cpp`, the second
step is enough.

A new C API capability reaches JS in three places: `src/librats_node.cpp`,
`lib/index.js`, and `lib/index.d.ts` (which carries the documentation), plus a
test in `test/test.js`.

## Publishing

```bash
npm test
npm publish          # runs `prepare` (copies the sources into native-src/) and builds once
```

## When the build fails

- `cmake --version` and a compiler on the PATH (`cl` from a Developer Prompt
  on Windows, `g++` elsewhere).
- Start clean: delete `build/` and `build-native/`, then `npm install`.
- Report problems at https://github.com/DEgITx/librats/issues.
